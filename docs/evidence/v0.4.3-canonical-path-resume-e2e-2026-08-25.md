# Codex Relay 0.4.3 canonical-path resume E2E — 2026-08-25

This record contains sanitized evidence for the production failure:

```text
move chat to Subscription 2: verify resumed chat history path:
existing chat history is outside the source sessions directory
```

No credential, control token, raw identity, prompt history, or unrelated local
path is included.

## Root cause

The affected task had valid, hash-matched replicas in Relay-managed account
homes and a 216 MB canonical checkpoint. Subscription 2 also had a stale
`threads.rollout_path` row in its private `state_5.sqlite`; that row still
pointed the task ID at the former native `.codex/sessions` rollout. ID-only
`thread/resume` therefore opened the stale path. Relay's verifier correctly
rejected it because it was outside Subscription 2's isolated home, but retrying
could never repair the mapping.

## Fix contract

After canonical materialization, Relay now sends the exact target-home JSONL in
the app-server `thread/resume.path` field. For a non-running task the current
app-server gives that path precedence over the stale ID index and repairs its
database row. Relay still accepts the resume only when a subsequent
`thread/read` returns a path inside the target managed history directory whose
SHA-256 and size equal the committed canonical checkpoint.

Reviewed older builds that reject `path` retry ID-only. That fallback remains
fail-closed under the same target-path and checkpoint verifier.
