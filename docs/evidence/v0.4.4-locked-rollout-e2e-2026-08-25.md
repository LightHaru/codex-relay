## Root cause and repair contract

On Windows, an app-server can retain a non-delete-sharing handle to its old
rollout even after the logical turn is idle. The verified temporary checkpoint
can then be read and hashed normally, but atomic rename over the loaded target
pathname fails with access denied.

Relay now asks the target worker to unsubscribe from the task before
materialization. Atomic replacement remains the normal installation path. If
Windows still denies replacement, Relay installs the same stable, hash-verified
checkpoint at a unique immutable sibling rollout in the target's managed
sessions directory. The exact installed path is passed to `thread/resume` and
ownership remains fail-closed until `thread/read`, target-home containment,
SHA-256, and size verification all succeed. A stale target worker may be
restarted only while idle; this operation addresses only the Router-owned child
process and never the native Store Codex process.
